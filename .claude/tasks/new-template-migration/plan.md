# План: переезд на новый шаблон деки + master-slide модель тактик

Статус: PR 1 + PR 2 сделаны 2026-08-17 (master-модель тактик, 84 книги → 3, чарты ищутся
сканом копии по книге-источнику). Включение нового шаблона — через env, см.
`new-template-env.md` в этой же папке. Осталось: новые токены (`{{so what N}}`,
`{{tactic n contr}}`, `{{total contr}}`) и чарты брейкдаун-аудитории.
Дата: 2026-08-13.

## 1. Цель

Перевести генерацию EOC/EOM-деки на новый дизайн шаблона и одновременно уйти от
«28 нарисованных тактик» к модели **один мастер-слайд → N копий в рантайме**, той же,
что уже работает для breakdown-слайдов.

Два результата:

1. дека собирается в новом дизайне;
2. следующий редизайн стоит 1–1.5 дня, а не 4–6.

### 3.2 Дельта по контенту (единственное, что требует кода)

1. **Platforms: новая колонка «SO WHAT?»** — фраза на тактику. Нужен `{{tactic n so what}}`
   + новое поле в Claude-промпте.
2. **Дивайдеры стали контентными**: «Campaign Approach» несёт список пунктов,
   «Campaign Results» несёт цифры (Impressions, CTV %). Решить: токены или статика.
3. **`{{proposal overview}}` разбит на 2 блока с заголовками** → 4 токена вместо 1, правка промпта.
4. Подписи HHI / Geo на Media Plan Overview — проверить, статика ли.
5. Финальный слайд переформулирован («STEP INTO THE AI ERA») — чистый дизайн.

Всё остальное, что выглядит новым, **уже есть в шаблоне**: `{{total imps/ctr/vcr}}`,
`publishers_observation_n_1..4`, `cr_takeaway_tactic n_1..4`, индексы аудиторий, device-таблица.

### 3.3 Master-модель уже написана

`RealSlidesProvider.addBreakdownSlides()` (~строка 480) делает ровно то, что нужно тактикам:

- `duplicateObject` с **заданным** id копии → `setObjectIds(Map.of(masterId, copyId))`;
- `emitRenumberedTokens` — scoped `replaceAllText` по копии, `n` → номер тактики;
- `updateSlidesPosition` — вставка после главного слайда;
- мастера удаляются отдельным безусловным проходом.

Чарт на копии ищется **сканом page elements** (`BreakdownChartBuilder.loadBreakdownChartElements`),
а не по id из конфига. Проблема «у копии неизвестные id детей» решена.

### 3.4 Чарты уже копируются в рантайме

`TacticChartBuilder.renderComboChart()` делает `driveCopier.copyFile(templateId, …)` на каждую
тактику, пишет данные и re-applies chart spec. Значит 28 книг-шаблонов на тип чарта —
с высокой вероятностью наследие POC и идентичны между собой.

## 4. Этапы

### PR 1 — схлопнуть книги-шаблоны чартов 84 → 3 (0.5 дня)

Делается **на старом шаблоне**, визуально ничего не меняет.

1. Через `spreadsheets.get` сверить 2–3 книги каждого типа (daily / monthly / dist):
   одинаковые ли вкладки, диапазоны и chart spec.
2. Если идентичны — свести `daily/monthly/dist-template-sheet-ids` к одному id на тип,
   `ChartTemplateCatalog` отдаёт его на любой номер тактики.
3. Один e2e-прогон на 2 и на 8 тактиках, сравнить деку с текущей.

Если книги окажутся разными — стоп, разбираемся; +0.5 дня, PR частично теряет смысл.

### PR 2 — тактик-слайд на master-модель (1.5–2 дня)

Тоже на старом шаблоне: он просто худеет на 27 слайдов.

1. В шаблоне оставить **один** тактик-слайд как мастер, токены с литеральным `n`
   (`{{tactic n imps}}` и т.д.) — так же, как у брейкдаунов.
2. Новый конфиг `tactic-master-slide-object-id` вместо `tactic-slide-object-ids`.
3. Переиспользовать `addBreakdownSlides`: детерминированный id копии
   (`BreakdownSlideNaming` дополнить `tacticSlideId(n)`), `emitRenumberedTokens`, позиционирование.
4. **Критично:** глобальный placeholder-pass отрабатывает ДО дублирования, поэтому на копии
   токен надо писать сразу значением, а не просто перенумеровывать — иначе `{{tactic 7 imps}}`
   уедет в готовую деку. В `addBreakdownSlides` это уже учтено, порядок шагов пайплайна
   для тактик-слайдов пересобрать под то же правило.
5. Чарты: `TacticChartBuilder` берёт объект чарта сканом копии вместо
   `daily/monthly/dist-slide-object-ids`. `loadTransforms` вызывать один раз и переиспользовать.
6. Чанкование `batchUpdate`: 28 duplicate + 28×~17 scoped replaceAllText в одном запросе — много.
7. `trimTactics` для тактик-слайдов больше не нужен (строить ровно N). Трим Platforms-групп
   и трим шита остаются.
8. Прогоны: 1 / 2 / 7 / 8 / 28 тактик + EOM, сравнение с текущей декой.

### PR 3 — переезд на новый дизайн (2.5–3.5 дня)

**Блокер:** нужны ~15 *пустых* мастер-макетов от дизайнера, а не заполненный сэмпл:
титул, 3 дивайдера, Media Plan, Strategic, Awareness, Platforms (группа на 7 строк),
тактик-слайд, 5 брейкдаун-слайдов, Thoughts (кампания), Thoughts (тактика),
Frequency, Recommendations, финал.

1. Разметка макетов токенами (0.5–1 д). Имена брать строго из старого шаблона —
   расхождение в пробеле/регистре ломает `findReplace`. Сверять скриптом-диффом
   «токены старого» vs «токены нового».
2. Плейсхолдеры чартов на мастерах + сбор ~10 object id (0.5 д).
3. Дельта §3.2 в коде: `CampaignResolvers` / `TacticResolvers`, промпты
   `ClaudeBatchPromptBuilder` (+ `EomPromptBuilder`), **и ячейки в EOC Sheet-шаблоне** —
   по текущей архитектуре шит единственный источник значений (0.5–1 д).
4. `eom-drop-slide-titles` под новые формулировки; `eom-drop-slide-object-ids` пересобрать (0.25 д).
5. E2E: 1 / 2 / 7 / 8 / 28 тактик + EOM, правки (0.5–1 д).
6. Раскатка: `SLIDES_TEMPLATE_ID` уже в env → старый шаблон остаётся дефолтом,
   новый включается переменной окружения. Переключение после приёмки.

## 6. Решения и границы

### 6.1 Platforms остаются группами по 7

Это не «слайд на тактику», а таблица 7 строк × 4 группы, где группа несёт ещё и
`{{Our results overview N}}`. Мастер-модель сюда не ложится. Динамическая таблица
(`insertTableRows`) — отдельная работа на +1–2 дня, **в этот план не входит**.
`results-slide-object-ids` / `summary-table-object-ids` остаются в конфиге.

### 6.2 Якорь позиции — по object id, не по индексу

Место вставки копий задаётся кодом. Якорить на object id мастера (как уже сделано
в `eom-drop-slide-object-ids`), иначе редактирование шаблона дизайнером тихо всё сдвинет.

### 6.3 Рефакторинг отдельно от редизайна

PR 1 и PR 2 идут на старом шаблоне. Иначе при первом расхождении не понять,
дизайн виноват или новая механика.
