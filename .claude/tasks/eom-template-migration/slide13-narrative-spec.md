Claude-предложению каждый; цифры на слайде — из таблицы METRIC (см. `slide13-fill-map.md`).

## Что важно знать перед реализацией

1. **Этих четырёх токенов нет в книге.** Они размечены только в `slide13.xml`; на вкладке General
   ячеек под них нет (проверено сканом шаблона: там из текстового только `{{tactic n goal}}`).
   Значит сейчас у пользователя нет шага, где он вычитывает и правит этот текст перед деком, —
   в отличие от всех остальных текстов EOM. Варианта два:
   - **добавить 4 ячейки в блок тактики на General** (как «Main slide N») — текст пишется на шаге
     генерации книги, правится руками, ридер отдаёт его в дек. Рекомендую: это ровно та схема,
     по которой уже живут `{{tactic n overview}}`, «SO WHAT?» и дашбордные takeaway;
   - генерировать на шаге деки — быстрее сделать, но текст неправим.
2. **Лимиты режутся нормализатором.** В `ClaudeResponseNormalizer` уже есть шкала таких констант
   (`PACING_TAKEAWAY_LIMIT = 140`, `WHAT_WE_DID_TEXT_LIMIT = 200`, `FOCUS_ITEM_LIMIT = 70`).
   Новые: 230 / 230 / 230 / 140.
3. **Форма вызова.** Это перtactic-текст, то есть по образцу уже существующих per-section
   per-tactic вызовов (keyless-массив со строгим позиционным приёмом), а не одного общего вызова:
   на 28 тактик один ответ не влезает в бюджет и разъезжается по позициям.
4. **Ручной override** — как у всех: `Tactic N what worked:` и т.д. в Adjustments.

## Решено и реализовано (2026-08-21)

Выбран **вариант 2 — генерация на шаге деки**, ячеек в книге нет и не будет.

Как сделано:

- `TacticPacingInput` / `TacticPacingMetric` / `TacticPacing` — DTO в `service/reports/dto`.
- `PacingNarrativeAssembler(+Impl)` — собирает вход из `flatReplacements` (METRIC-таблица
  тактики читается по тем же суффиксам, что `SheetPlaceholderReaderImpl.METRIC_ROW_SUFFIXES`,
  чтобы колонка не могла значить на двух сторонах разное) и пишет 4 токена обратно.
  Значение, которое уже лежит в карте (пришло из книги), не перезатирается — формулировка
  пользователя старше сгенерированной. Тактика без ответа получает прочерк, не сырой токен.
- `ClaudeClient.tacticPacing` + `RealClaudeClient.pacingFrom` — один вызов на тактику,
  JSON с четырьмя именованными полями (не массив: позиционного дрейфа нет).
  Лимиты 230/230/230/140, буферизуются в промпте как везде.
- `ClaudeBatchPromptBuilder.buildTacticPacingPrompt` — инструкция и бриф до
  `CACHE_BREAKPOINT`, таблица тактики после. Пустая таблица => вызова нет.
- `ReportGenerationServiceImpl.fillPacingNarrative` — только EOM, после
  `fillEomDashboards`/`fillContributions` и до `createDeck`, все тактики параллельно.

Ручной override через `Tactic N what worked:` в Adjustments НЕ сделан: сейчас старшинство
даёт только значение, уже лежащее в карте (т.е. ячейка в книге, если её когда-нибудь добавят).
